# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.



### Данные
В приложении используются две основные сущности данных: товары и покупатели. Для их описания разработаны следующие интерфейсы:

#### Интерфейс IProduct
typescript
interface IProduct {
  id: string; - уникальный идентификатор
  description: string; - описание
  image: string; - путь к изображению
  title: string; - название
  category: string; - категория
  price: number | null; - цена
}
Назначение: Описывает структуру товара в каталоге. Содержит уникальный идентификатор, название, описание, путь к изображению, категорию и цену (может быть null, если товар недоступен для покупки).

#### Интерфейс IBuyer
typescript
interface IBuyer {
  payment: TPayment; - способ оплаты
  email: string; - email
  phone: string; - номер телефона
  address: string; - адрес доставки
}
Назначение: Описывает данные покупателя, необходимые для оформления заказа. Содержит способ оплаты, email, номер телефона и адрес доставки.

Тип TPayment
typescript
type TPayment = 'cash' | 'card';
Назначение: Union-тип, ограничивающий способы оплаты двумя вариантами: 'cash' (наличными) или 'card' (картой).

### Модели данных
Работа с данными реализована через три класса-модели, разделённые по зонам ответственности. Классы называются "Модели данных" и инкапсулируют хранение и операции с соответствующими сущностями.

#### Класс ProductCatalog
Назначение и зона ответственности: Хранит полный каталог товаров магазина и управляет выбором товара для детального просмотра. Предоставляет методы для работы с массивом товаров и поиска по ID.

Конструктор: constructor() — не принимает параметров, инициализирует пустые коллекции.

Поля:

private products: IProduct[] — массив всех доступных товаров каталога.

private selectedProduct: IProduct | null — товар, выбранный пользователем для подробного просмотра.

Методы:

saveProducts(products: IProduct[]): void — сохраняет переданный массив товаров в коллекцию каталога.

getProducts(): IProduct[] — возвращает копию массива всех товаров.

getProductById(id: string): IProduct | null — возвращает товар по уникальному ID или null, если товар не найден.

setSelectedProduct(product: IProduct): void — устанавливает товар для детального просмотра.

getSelectedProduct(): IProduct | null — возвращает выбранный для просмотра товар.

#### Класс Cart
Назначение и зона ответственности: Управляет корзиной покупок — товарами, выбранными пользователем. Поддерживает операции добавления/удаления, подсчёт общей стоимости и количества товаров.

Конструктор: constructor() — не принимает параметров, создаёт пустую корзину.

Поля:

private items: IProduct[] — массив товаров, находящихся в корзине.

Методы:

getItems(): IProduct[] — возвращает копию массива товаров корзины.

addItem(product: IProduct): void — добавляет товар в корзину (дубликаты обрабатываются по логике проекта).

removeItem(product: IProduct): void — удаляет товар из корзины.

clear(): void — полностью очищает корзину.

getTotalPrice(): number — возвращает общую стоимость всех товаров (сумма цен).

getItemCount(): number — возвращает общее количество товаров в корзине.

hasItem(id: string): boolean — проверяет наличие товара в корзине по ID.

#### Класс Buyer
Назначение и зона ответственности: Хранит контактные и платежные данные покупателя. Поддерживает частичное заполнение (без потери других данных), валидацию и очистку.

Конструктор: constructor() — не принимает параметров, все поля инициализируются пустыми значениями.

Поля:

payment: TPayment | null — выбранный способ оплаты.

email: string — email-адрес покупателя.

phone: string — номер телефона покупателя.

address: string — адрес доставки.

Методы:

setPayment(payment: TPayment): void — устанавливает способ оплаты.

setEmail(email: string): void — устанавливает email-адрес.

setPhone(phone: string): void — устанавливает номер телефона.

setAddress(address: string): void — устанавливает адрес доставки.

getData(): IBuyer — возвращает объект с заполненными данными покупателя.

clear(): void — сбрасывает все поля на начальные значения.

validate(): Partial<Record<keyof IBuyer, string>> | null — валидирует все поля. Возвращает объект ошибок {поле: 'текст ошибки'} для невалидных полей (пустые значения) или null, если все поля валидны.



### Классы представления
В приложении используются классы представления, каждый из которых отвечает за свой блок разметки. Все компоненты представления наследуются от базового класса Component и работают по принципу передачи данных через render.

#### Класс Card
Базовый класс для карточек товаров. Класс является родительским для трёх шаблонов карточек и содержит общий функционал, который используется во всех дочерних классах.

Назначение: отображение общей структуры карточки товара.
Общий функционал: установка названия, изображения, категории, цены и идентификатора товара.

#### Класс CatalogCard
Карточка товара в каталоге. Наследуется от Card и используется для отображения товара на главной странице.

Назначение: вывод товара в списке каталога.
Отображает: изображение, название, категорию и цену товара.

#### Класс PreviewCard
Карточка товара для отображения в модальном окне. Наследуется от Card и используется для показа подробной информации о товаре.

Назначение: вывод полной информации о товаре.
Отображает: изображение, название, категорию, цену и описание товара.

#### Класс BasketCard
Карточка товара в корзине. Наследуется от Card и используется для отображения товара в списке корзины.

Назначение: вывод товара, добавленного в корзину.
Отображает: название товара, цену и кнопку удаления.

#### Класс Form
Базовый класс для форм. Класс является родительским для двух форм и содержит общий функционал для работы с полями, ошибками и состоянием кнопки отправки.

Назначение: обработка состояния формы и валидации данных.
Общий функционал: установка значений полей, отображение ошибок, управление активностью кнопки отправки.

#### Класс OrderForm
Форма оформления заказа. Наследуется от Form и содержит данные для выбора способа оплаты и ввода адреса доставки.

Назначение: ввод способа оплаты и адреса доставки.
Поля: кнопки выбора способа оплаты, поле адреса доставки, кнопка перехода к следующему шагу.

#### Класс ContactsForm
Форма контактных данных покупателя. Наследуется от Form и используется для ввода email и телефона.

Назначение: ввод контактных данных покупателя.
Поля: поле email, поле телефона, кнопка отправки заказа.

#### Класс Modal
Класс модального окна. Не имеет дочерних классов и не является родительским для других компонентов. Внутри модального окна может отображаться любой самостоятельный компонент представления.

Назначение: управление открытием, закрытием и содержимым модального окна.
Поля: оверлей, контейнер содержимого, кнопка закрытия.

#### Класс Gallery
Компонент каталога товаров. Наследуется от Component и содержит массив карточек товаров.

Назначение: отображение списка товаров на главной странице.
Поля: массив карточек товаров.

#### Класс Header
Компонент шапки страницы. Наследуется от Component и содержит два HTML-элемента: заголовок и кнопку корзины со счётчиком товаров.

Назначение: отображение верхней части страницы.
Поля: заголовок сайта, кнопка корзины, счётчик количества товаров в корзине.

#### Класс Basket
Компонент корзины товаров. Наследуется от Component и отображает список товаров, итоговую стоимость и кнопку оформления заказа.

Назначение: отображение товаров, добавленных в корзину.
Поля: список карточек корзины, итоговая сумма, кнопка оформления заказа.


### События приложения
В приложении используется событийно-ориентированный подход. Модели данных генерируют события при изменении состояния, а компоненты представления уведомляют Презентер о действиях пользователя через события или обработчики.

#### События моделей данных
catalog:changed
Событие изменения каталога товаров. Генерируется после загрузки или обновления списка товаров в модели ProductCatalog. Используется для обновления отображения каталога на странице.

product:selected
Событие изменения выбранного для просмотра товара. Генерируется при установке нового выбранного товара в модели ProductCatalog. Используется для открытия карточки товара в модальном окне.

cart:changed
Событие изменения содержимого корзины. Генерируется при добавлении, удалении или очистке товаров в модели Cart. Используется для обновления счётчика корзины, списка товаров и итоговой стоимости.

buyer:changed
Событие изменения данных покупателя. Генерируется при обновлении любого поля в модели Buyer. Используется для валидации формы и хранения актуальных данных заказа.

#### События представлений
card:selected
Событие выбора карточки для просмотра. Генерируется компонентом карточки товара в каталоге при нажатии на неё. Используется для передачи выбранного товара в Презентер.

card:buy
Событие нажатия кнопки покупки товара. Генерируется компонентом карточки товара в окне предпросмотра. Используется для добавления товара в корзину или перехода к следующему состоянию.

basket:remove
Событие нажатия кнопки удаления товара из корзины. Генерируется компонентом карточки товара в корзине. Используется для удаления товара из корзины в Презентере.

basket:open
Событие нажатия кнопки открытия корзины. Генерируется компонентом Header при нажатии на кнопку корзины. Используется для открытия модального окна с корзиной.

order:open
Событие нажатия кнопки оформления заказа. Генерируется компонентом Basket при нажатии на кнопку оформления. Используется для перехода к первой форме оформления заказа.

order:submit
Событие нажатия кнопки перехода ко второй форме оформления заказа. Генерируется компонентом первой формы оформления заказа. Используется для перехода к форме контактных данных покупателя.

contacts:submit
Событие нажатия кнопки оплаты или завершения оформления заказа. Генерируется компонентом второй формы оформления заказа. Используется для отправки данных заказа на сервер.

form:changed
Событие изменения данных в формах. Генерируется при изменении любого поля в формах оформления заказа и контактных данных. Используется для обновления модели покупателя и проверки валидности формы.
